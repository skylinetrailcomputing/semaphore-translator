# Shared contract — single source of truth

These language-neutral files define behavior that **must be identical**
across the iOS and Android implementations. Both platforms load and
parse them; neither hardcodes their contents.

| File | Role |
|------|------|
| `semaphore_alphabet.json` | (left,right) arm-position → character mapping, position model, numeric-mode signs + digit map, and the frozen model label order. |
| `keypoint_contract.json` | The post-adapter 6-keypoint representation both platform adapters must emit (spec §3.2/§4.1/§4.2): names + order, `[x,y,confidence]` shape, the y-up/signer-perspective frame, the confidence gate, and the frozen 12-float model-input order. Human spec: `ADAPTER-CONTRACT.md`. |
| `semaphore_config.json` | Frozen runtime constants (spec §4.4): angle tolerance, confidence floor, commit/debounce timing, smoothing window. The flat timing keys are the **Learn** (front-camera) profile; `timing_profiles.interpret` overrides them for the rear-camera **Interpret** fork — selected by lens at the committer-construction site (faster commit for faster signers). See [ADR 0009](../docs/adr/0009-interpret-timing-profile.md). |
| `test_vectors.json` | Input keypoint vectors → expected decoded output. The parity test runs these through both platforms' full feature-extraction + classification path; results must match exactly. **Untimed** — one frame per committed symbol. |
| `temporal_vectors.json` | **Timed** frame sequences → the string the temporal committer commits (smoothing + hold-to-commit + debounced mode switch), for the **Learn** timing profile. Separate from `test_vectors.json` because the committer is time-dependent. Drives the Epic-4 committer parity ports (#4.2/#4.3). See [ADR 0004](../docs/adr/0004-temporal-commit-contract.md). |
| `temporal_vectors_interpret.json` | Same timed-committer fixtures for the **Interpret** timing profile (rear-camera fork, ADR 0009): the faster `COMMIT_HOLD_MS` narrows the double-letter re-arm window, so it carries its own `REST_REARM` and a discriminating `[350,600)` sequence that commits `'L L'` where Learn commits `'LL'`. Generated by the same `gen_temporal_vectors.py` run; drives the per-platform Interpret parity tests. |
| `drill_contract.json` | The Learn **drill engine** contract (Epic 6a, #69): the *target → session → match-detector* model, the match rule, and the stay-until-success lifecycle. Descriptive — the behavioural enforcement is `drill_vectors.json`. Sits **downstream of the committer** (consumes committed characters only). See [ADR 0007](../docs/adr/0007-drill-engine-contract.md). |
| `drill_vectors.json` | Drill-engine parity vectors: a target passage + the committed-character stream a signer produces → the per-step `matched`/`index`/`complete` the engine decides. **No keypoints, no timing** — only emitted characters — because the drill engine is downstream of the committer. Drives the 6a-1 `DrillSession` parity ports. |
| `source_contract.json` | The Learn passage **source** contract (Epic 6a, #71): the sanitisation rule that maps arbitrary text → the frozen ASCII target alphabet (`A–Z / 0–9 / SPACE`), the machine-checkable `supported_chars`, and the `max_targets` cap. Descriptive — the behavioural enforcement is `sanitize_vectors.json`. Sits **upstream of the drill engine** (produces the string it consumes). See [ADR 0008](../docs/adr/0008-learn-source-sanitization.md). |
| `sanitize_vectors.json` | Passage-source parity vectors: a raw input string → the sanitised target string. **No keypoints, no timing** — plain string→string, because the source is pure logic upstream of the engine. Drives the 6a-3 `PassageSource.sanitize` parity ports. Stored `ensure_ascii=True` (inputs carry deliberate non-ASCII scalars). |
| `committed_text_vectors.json` | Readout-buffer space-coalescing parity vectors: a sequence of committer tokens → the resulting `committedText` buffer. **No keypoints, no timing** — plain string→string, because the buffer is pure logic downstream of the committer. The rule: never a leading space, never two in a row (a single trailing space is kept). Drives the `CommittedText.append` parity ports. See [ADR 0010](../docs/adr/0010-committed-text-space-coalescing.md). |
| `stock_passages.json` | Bundled "sight-read" stock passages for Learn (Epic 6a, #71): `{id, hint, text}`. Shared **content** (not a behavioural contract), loaded verbatim by both apps so the picker list is identical. Each `text` is authored already-clean (`sanitize(text) == text`, asserted by the generator + both parity tests); `hint` is content-neutral and never reveals the text (sight-read). |
| `disclaimer.json` | The first-launch disclaimer text both apps show before the Home fork (Epic 6b, #87) — *not* part of the decode contract, but loaded verbatim by both platforms so the wording, and the **SHA-256 consent hash both compute over this file's raw bytes**, are identical. The hash is the consent key: any edit (including `version`) re-shows the gate. The full governing texts are the hosted EULA / Privacy Policy linked inside. |

## ✅ The alphabet contract is VERIFIED (frozen 2026-06-19, Epic 1)

`semaphore_alphabet.json` carries `_verification.status = "VERIFIED"`.
Every A–Z `(left,right)` pair was read directly from the canonical
Wikipedia/anbg per-letter chart (the actual raster image, not from
memory or a text summary), converted from the chart's **observer**
perspective to the frozen **signer's** perspective by a calibrated
horizontal mirror, and cross-checked against the classic "circles"
construction. The numerals sign was read from `File:Semaphore Numeric`.
See [`ALPHABET-VERIFICATION.md`](ALPHABET-VERIFICATION.md) for the full
per-letter table, sources, and the calibration method.

What the freeze settled (the two problems found at scaffolding time):

1. **id↔angle reconciliation (#9).** The frozen frame is **`+x` =
   signer's right, `+y` = up, angle CCW from `+x`**. Under it, spec §4.2
   and `semaphore_alphabet.json._position_model` now assign identical
   angles to all 8 ids (0:−90, 1:−45, 2:0, 3:45, 4:90, 5:135, 6:180,
   7:−135) and identical direction names. The earlier spec-vs-JSON
   mirror-swap on ids 2/3/5/6, and the spec's down-diagonal label
   inconsistency, are both resolved — the diagonal labels are correct
   under `+x` = right.

2. **Letter pairs (#8).** Reading the image corrected **9** pairs from
   the prior unverified draft — **J, P, Q, R, S, T, U, W, Y** — plus the
   **NUMERALS** sign `(left up-left, right up)`. The numeric half
   (A=1…I=9, **K=0**, J=letters-shift) and the 8-octant model were
   already correct and are confirmed. Note: letter **I** is *unchanged*
   `(down-right, up-right)`; a prior text-only cross-check had wrongly
   flagged it, and reading the actual chart restored the original value.

The source charts are all drawn in the **observer's** perspective
(confirmed verbatim: Wikipedia "as they would appear when facing the
signalperson"; dCode "always presented in receive mode"). The single
mirror + y-flip that converts to the signer's frame lives **only** in
the per-platform adapter (spec §3.2/§4.2).

With the alphabet frozen, `test_vectors.json` is now populated (Epic 1,
#12): one clean post-adapter vector per letter A–Z plus NUMERALS, REST,
arm-swapped positives for the order-insensitive letters (H, I, O, W, X,
Z), two indeterminate cases, and sequences exercising both numeric-mode
transitions. It is generated by `tools/gen_test_vectors.py` (`uv run`),
which re-decodes every vector and asserts the expected output before
writing — regenerate it after any change to `semaphore_alphabet.json`
or `semaphore_config.json` rather than hand-editing.

## 📐 The adapter contract is FROZEN (Epic 2, #13)

`keypoint_contract.json` + [`ADAPTER-CONTRACT.md`](ADAPTER-CONTRACT.md)
define the post-adapter 6-keypoint representation both platform adapters
must emit: the six keypoint names and their order, the `[x,y,confidence]`
shape, the normalized **y-up, signer's-perspective** frame, the
confidence gate, and the frozen **12-float model-input order**. The two
transforms that reach this frame — the y-flip and the front-camera mirror
— happen **exactly once, in the per-platform adapter, and nowhere else**;
the contract spells out the left/right anatomical hazard that makes the
mirror the project's most error-prone step. `test_vectors.json` is
defined as this contract's *output*, so the parity harness (#14) validates
everything downstream of the adapter, while native fixtures (Epic 3)
validate the adapter itself.

## ⏱️ The temporal commit contract is FROZEN (Epic 4, #31)

[ADR 0004](../docs/adr/0004-temporal-commit-contract.md) freezes the
**temporal committer**: smoothing votes on the mode-independent pose
symbol (`classify`), a candidate held for `COMMIT_HOLD_MS` commits (running
`interpret` for the emit + mode flip, so **mode flips only on a committed
control pose**), distinct symbols stream on their holds while the *same*
symbol re-commits only across an indeterminate gap ≥ `INTER_CHAR_GAP_MS`,
and true signer-loss hard-resets to `LETTERS`. Time is injected, never read
from a clock. `temporal_vectors.json` is generated by
`tools/gen_temporal_vectors.py` (`uv run`), which re-runs the reference
committer over every sequence and asserts the committed output before
writing — the same self-validating discipline as `test_vectors.json`. Both
generators share one Python reference (`tools/_semaphore_ref.py`) so the
per-frame and timed fixtures cannot drift. The committer ports themselves
are #4.2 (iOS) / #4.3 (Android); this ticket froze the contract only.

The committer **timing forks by camera lens** ([ADR 0009](../docs/adr/0009-interpret-timing-profile.md),
Epic 6a #75): the front-camera **Learn** profile is those frozen flat
constants; the rear-camera **Interpret** profile overrides them via
`semaphore_config.json`'s `timing_profiles.interpret` (a faster
`COMMIT_HOLD_MS` for faster real-world signers). The committer *code* is
untouched — it is already parameterized by `CommitTiming` — and the
decode/adapter path stays lens-agnostic (ADR 0006). `gen_temporal_vectors.py`
emits one self-validating file per profile (`temporal_vectors.json` +
`temporal_vectors_interpret.json`); the Interpret values are a starter that
#76 (6a-8) tunes against footage.

## 🎯 The drill engine contract is FROZEN (Epic 6a, #69)

[ADR 0007](../docs/adr/0007-drill-engine-contract.md) freezes the **Learn
drill engine** — the *target → session → match-detector* the Learn modes
collapse onto — **downstream of the committer**: it observes only the
characters the committer emits (A–Z / 0–9 / SPACE) and never touches
keypoints, timing, or any decode state, so it cannot perturb the
decode/adapter/commit core (parity risk ~0). The match rule is small:
ASCII-uppercase both the emit and the current target, a hit advances the
target index, reaching the end is `COMPLETE`; under stay-until-success (the
only 6a-1 lifecycle) a miss is a no-op. `drill_vectors.json` is generated by
`tools/gen_drill_vectors.py` (`uv run`), which re-runs the reference
`DrillSession` over every sequence and asserts the intended final state
before writing — the same self-validating discipline as the other fixtures,
but with **no decode dependency** (the vectors are plain committed-character
streams, so this generator imports no geometry). The two platform ports are
the 6a-1 `DrillSession` (iOS `ios/Sources/Core/DrillSession.swift`, Android
`.../core/DrillSession.kt`); the session HUD + celebrate that consume the
engine are 6a-2, and the passage→targets source is 6a-3.

## ✍️ The Learn passage source is FROZEN (Epic 6a, #71)

[ADR 0008](../docs/adr/0008-learn-source-sanitization.md) freezes the **Learn
passage source** — the layer that turns arbitrary custom/stock text into the
already-validated target string the drill engine consumes, **upstream of the
engine** (it never touches the decode/adapter/commit/drill core). The one
parity-critical behaviour is `sanitize()`: iterate by **scalar / code point**
(Swift `unicodeScalars`, Kotlin `Char`, Python code point) — *not* graphemes;
**ASCII-only** uppercase (`a–z → A–Z` by value, never the locale-aware
whole-string upper that would expand `ß → "SS"`); keep `A–Z / 0–9`; collapse
`{SPACE,TAB,LF,CR}` runs to one space and trim; drop everything else (no
transliteration). `sanitize_vectors.json` is generated by
`tools/gen_sanitize_vectors.py` (`uv run`), which re-runs the reference over
every authored `(input → expected)`, asserts each before writing, asserts every
`stock_passages.json` text is already-clean, and cross-checks `supported_chars`
against the reference output alphabet — the same self-validating discipline as
the other fixtures, with **no decode dependency**. The two platform ports are
`PassageSource.sanitize` (iOS `ios/Sources/Core/PassageSource.swift`, Android
`.../core/PassageSource.kt`); the custom-passage + sight-read source IA that
feeds them is also 6a-3.

## ␣ The readout-buffer space rule is FROZEN

[ADR 0010](../docs/adr/0010-committed-text-space-coalescing.md) freezes how a
committer token joins the user-visible readout buffer (`committedText`),
**downstream of the committer** (it never touches the decode/adapter/commit/drill
core). It is the live/incremental analogue of `sanitize()`: where the source
sanitiser trims+collapses whitespace over a whole typed string in one batch,
`CommittedText.append` enforces the same shape one committed token at a time as a
read unfolds — **never a leading space, never two spaces in a row** (a single
*trailing* space is kept; it is the in-progress word separator). It exists because
even the half-open REST design (ADR 0005) still lets two SPACE tokens through — a
held REST before any letter (a *leading* space) and a brief indeterminate gap
between two REST runs (a *double* space) — and "is this a leading/redundant space?"
is a property of the buffer, which outlives the committer's no-signer `reset()`.
`committed_text_vectors.json` is generated by
`tools/gen_committed_text_vectors.py` (`uv run`), which re-folds the reference
`append_committed()` over every authored `(emits → expected)` and asserts each
before writing — the same self-validating discipline as the other fixtures, with
**no decode dependency**. The two platform ports are `CommittedText.append` (iOS
`ios/Sources/Core/CommittedText.swift`, Android `.../core/CommittedText.kt`).
